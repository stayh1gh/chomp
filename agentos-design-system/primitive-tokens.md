# Primitive tokens

Raw hex only. Loaded by `generate-tokens` alone — never during component builds or UI work; use `semantic-tokens.md` for anything with a purpose attached.

This system is dark-only (no light theme), so the usual "stop 0 = white / stop 500 = brand on white" convention is inverted in effect: stops toward `0` are the near-white values used sparingly for high-emphasis text and highlight fills, and stops toward `900` are the near-black surfaces this UI actually lives in. Only `500` on each brand hue, and every value in `surface`/`text`, is pixel-sampled from the source (Figma file `sM9waRlCvYsI8tNcB8TQrp`, node 1:12996). The rest of each 12-stop hue scale is generated by holding hue constant and sweeping lightness — provided for future tint/shade needs (subtle backgrounds, hover fills) beyond what's shipped today, and MAY be adjusted for contrast when a component actually needs one of those stops.

## surface (sampled, non-linear — a 4-step ladder, not a scale)

```yaml
surface-0: '#09090a'   # --page. Outermost canvas.
surface-1: '#121213'   # --panel. The one app panel.
surface-2: '#1a1a1b'   # --card. Cards, setting rows, outline badge fill.
surface-3: '#242424'   # --card-inset. One nesting level inside a card (description well only).
surface-accent-tile: '#212121'  # --logo-tile. Brand mark tile only.
surface-border: '#1a1b1d'       # --border. Default hairline.
surface-border-strong: '#2f3033' # --badge-border. Badge outline, select/input border.
surface-divider: '#27292b'      # --card-divider. Card footer rule above Approve.
```

## text (sampled — all light values; this UI has no dark-on-light text)

Token path is `text.*` throughout this doc and `tokens.json`. In `tokens.css` these are emitted
as `--ink-*`, not `--text-*` — Tailwind 4 reserves `--text-*` for its own font-size scale, and
these are colors. Same token, different CSS variable name; see the note at the top of `tokens.css`.

```yaml
text-0: '#ffffff'  # --fg
text-1: '#e3e4e6'  # --fg-strong
text-2: '#d8d8da'  # nav-item hover
text-3: '#b8b8b8'  # --fg-body
text-4: '#98999c'  # --fg-muted
text-5: '#959597'  # --fg-subtle
text-6: '#929294'  # --fg-nav
text-7: '#6b6b6e'  # .muted utility
text-8: '#4a4a4d'  # column-empty / unset subtask dot
```

## a11y-corrected variants (not sampled — computed to clear WCAG AA where a sampled value fails)

`generate-tokens`' contrast check (see `accessibility.md`) found the raw sampled values below fail 4.5:1 against the surface they're actually used on as text. The sampled hex stays recorded above/below as a faithful record of the Figma export; the semantic aliases that render as text resolve to these corrected stops instead.

```yaml
text-7-a11y: '#7c7c7e'          # ink-faint, corrected. Sampled text-7 (#6b6b6e) = 3.75:1 on canvas, fails. This = 4.78:1.
ink-on-status-fill: '#09090a'   # = neutral.900. Text on success/warning/danger badge fills — sampled white text
                                 # (text-0) only clears 4.5:1 on the brand (indigo) fill; on the lighter, more
                                 # saturated green/orange/red fills white drops to 2.2–3.3:1. Near-black clears 6–9:1.
```
